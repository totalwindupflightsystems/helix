# GAP-001 — CLI subcommand hang / undiscoverable-command fix

## Problem

1. `helix <unknown>` errors fast (0.1s, rc=1) but prints
   `Available subcommands: estimate, identity, marketplace, negotiate, prompt,
   release, sandbox` — only the 7 delegated sibling binaries. The 40+ built-in
   subcommands (status, doctor, spec, adr, contract, channel, source, ...) are
   hidden from the error, so a user cannot tell the CLI is working or that
   `helix status` exists.
2. `execSubcommand` uses bare `cmd.Run()` with no timeout — a hung sibling
   binary (e.g. a bare HTTP call hitting a 140s TCP-connect timeout) hangs the
   unified `helix` wrapper indefinitely with zero output.

## Fix

1. Unknown-subcommand error lists ALL available subcommands (built-ins +
   delegated) with a `Run 'helix --help' for descriptions` hint; still exits
   instantly (rc=1).
2. `execSubcommand` runs the child under a bounded context (default 120s,
   `HELIX_SUBCOMMAND_TIMEOUT` env override) and returns a clear timeout error
   naming the subcommand, the bound, and the env var. Child is killed on
   timeout.
3. Regression tests: (a) unknown-subcommand error contains built-ins
   (status/doctor/spec) + delegated (identity/estimate) + help hint;
   (b) execSubcommand times out a hung child (`sh -c 'sleep 30'` with
   HELIX_SUBCOMMAND_TIMEOUT=1s) with a clear error.

## Acceptance criteria (from board)

- Unknown subcommands exit immediately with usage error (cobra default).
- Any real subcommand that contacts external services gets a timeout + clear
  error.
- PASS: `timeout 20 ./helix status` exits <=20s with a clear error/usage message.
- PASS: `./helix --help` completes in <5s.
- gitreins guard passes 4/4; full suite passes with TMPDIR=/dev/shm redirect.
