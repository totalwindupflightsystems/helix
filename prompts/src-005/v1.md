# SRC-005 — Dispatcher wiring: inject source tools at task dispatch

## Context

SPEC-025 (specs/multi-source-integration.md) §6 / §9.5: the Ralph Loop dispatcher
injects capability-gated source tools per agent. pkg/source (SRC-001..004) is
complete: config parsing, Muster bridge (OpenAPI → MCP tools), capability
gating (Gateway.Filter), per-source rate limiting (RateLimitManager). pkg/source
currently has ZERO dependents — SRC-005 is the wiring task that gives it one.

## Requirements

- Agents carry capability claims (identity.CapabilityClaim: domain + strength 1-10).
- At task dispatch, the assigned agent receives only the source tools matching
  its claims: strength 7-10 → read-write tools; 1-6 → read-only (GET/HEAD/OPTIONS);
  no matching claim → zero source tools (SPEC-025 §5).
- Source.AllowedAgents and Source.ReadOnly honored end-to-end.
- Per-source rate limiting applied before source-tool execution
  (RateLimitManager.Wait keyed on source name).
- No pkg/source changes, no cmd/helix changes (SRC-006 owns the CLI).

## Design freedom

The seam is underspecified by the spec: worker chooses the injection point
(Dispatch / ForgejoLoop), the carrier (WorkItem/DispatchResult tool field),
and the wiring component (SourceToolInjector or Dispatcher methods), within
the acceptance criteria in the dispatch prompt (AC1-AC9).

## Out of scope

- CLI (`helix source ...` — SRC-006)
- Changes to pkg/source behavior
- UI / canopy paths (UI-001..004, blocked cross-project)
