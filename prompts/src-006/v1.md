# SRC-006 — Source CLI: helix source add/list/test/tools

## Context

SPEC-025 (specs/multi-source-integration.md) §7 / §8: the CLI surface for
multi-source integration. pkg/source is complete (SRC-001..004): config
parsing + validation (config.go), Muster bridge (muster_bridge.go,
OpenAPI → MCP tools), capability gating (gateway.go), per-source rate
limiting (ratelimit.go). SRC-005 wired the dispatcher. SRC-006 adds the
operator-facing CLI: `cmd/helix/source.go`.

## Requirements

- `helix source add    --name STRING --type [postgres|rest|local] --spec PATH`
  — add/update a source in `.helix/sources.yaml` (create file + parent dir
  when missing, preserve existing entries, validate before writing).
- `helix source list   [--enabled]` — table of sources sorted by name
  (name, type, read_only, rate_limit, allowed_agents).
- `helix source test   --name STRING` — validate config, check spec file
  presence, type-specific connectivity probes; Muster-down = warning, not
  failure; exit 2 with clear message on real failures.
- `helix source tools  --name STRING` — generate via
  MusterBridge.GenerateToolsFromSource and list MCP tools
  (name, method, path, auth_required); exit 2 if source missing or Muster
  unreachable.

## Conventions

- Follow cmd/helix/contract.go pattern: parseXFlags + runXWithDryRun,
  wired in cmd/helix/main.go switch via RunWithObs; exit codes 0/2;
  --dry-run prints intent without writing.
- New files only: cmd/helix/source.go + cmd/helix/source_test.go
  (plus minimal `Enabled` field on pkg/source Source if --enabled needs it).
- No new dependencies, no go.mod/go.sum changes, no pkg/source behavior
  changes beyond the optional Enabled field.
- Do NOT commit — leave changes in the working tree (foreman commits).
- Prompt: prompts/src-006/v1.md
