# SPEC-GAP-001 — contract diff arg order mismatch

## Goal

Resolve the `helix contract diff` argument-order discrepancy: help/error text says
`<old> <new>` but the implementation loads the FIRST positional as the NEW contract
and the SECOND as the OLD one. Verify against specs/*.md, then align the user-facing
text with the actual (library-consistent) behavior.

## Findings (verified by foreman, 2026-08-05)

1. **No spec authority**: grep of specs/*.md, SPECIFICATION.md, README.md, AGENTS.md,
   docs/, prompts/ found NO document that pins the `contract diff` positional order.
   The resolution is by codebase convention.
2. **Library convention is new-first**: `pkg/contract/breaking.go:10` declares
   `func DetectChanges(new, old *Contract) []BreakingChange` — the library's
   parameter order is (new, old).
3. **CLI parsing matches the library**: `cmd/helix/contract.go:72-75` assigns the
   first positional to `f.id` (loaded as NEW in runContractDiff) and the second to
   `f.oldID` (loaded as OLD). `runContractDiff` (contract.go:258-271) is coherent:
   `newC = Load(flags.id)`, `oldC = Load(flags.oldID)`, `DetectChanges(newC, oldC)`.
4. **The outliers are the user-facing strings** (only 3 sites in the whole repo):
   - `cmd/helix/contract.go:89` — help text `helix contract diff <old> <new>`
   - `cmd/helix/contract.go:260` — error `contract diff requires <old-id> <new-id>`
   - `cmd/helix/contract_test.go:324` — assertion on that error string
   - plus the stale NOTE comment at `cmd/helix/contract_test.go:331-333` documenting
     the discrepancy ("help text says <old> <new>; the code's effective contract is
     diff <new> <old>")
5. **Tests lock the actual behavior** (`diff new-1 old-1` → "1 breaking change(s)
   between "old-1" and "new-1""), and the behavior is correct per the library.

## Decision

Fix the HELP/ERROR TEXT to `<new> <old>` (NOT the parsing). Rationale:
- The library signature `DetectChanges(new, old)` is the deepest contract and the
  CLI already follows it consistently.
- Changing the arg order would be a breaking behavioral change to existing
  scripts/users with zero spec mandate.
- Minimal diff; no behavior change; tests keep validating real behavior.

## Required changes

1. `cmd/helix/contract.go:89` — help line becomes:
   `  helix contract diff <new> <old>    Show breaking changes between versions`
2. `cmd/helix/contract.go:260` — error becomes:
   `contract diff requires <new-id> <old-id>`
3. `cmd/helix/contract_test.go:324` — update the assertion string to
   `contract diff requires <new-id> <old-id>`.
4. `cmd/helix/contract_test.go:331-333` — remove the NOTE comment (discrepancy
   resolved); replace with a one-line comment locking the documented order, e.g.
   `// Contract: diff <new> <old> — first positional is new, second is old.`
5. Do NOT touch parseContractFlags, runContractDiff logic, DetectChanges, or any
   other file. No go.mod/go.sum changes. No new dependencies.
