What Makes Helix Different

Not a bot. A teammate. Agents get real Forgejo accounts with SSH keys. Their commits are real commits. Their PRs are real PRs. When something breaks, the audit trail shows which agent wrote it, which agent reviewed it, what evidence was considered, and what the multi-model consensus was.

Trust is earned, not assigned. Agents start at Provisional tier. Clean merges earn trust. Incidents decay it. Trust directly gates canary deployment speed — Veteran agents ship to production in hours; Provisionals take days.

6. Getting Started — Quickstart Guide

Prerequisites

  • Go 1.26+ (build from source) or Docker (containerized)
  • Forgejo instance (self-hosted git forge)
  • Chimera instance (multi-model deliberation — optional for basic flow)

Quickstart — Docker Compose

# 1. Clone the repo
git clone https://github.com/totalwindupflightsystems/helix.git
cd helix

# 2. Set up environment
cp .env.example .env
# Edit .env with your Forgejo URL, Chimera URL, and model API keys

# 3. Start the stack
./scripts/up.sh

# 4. Provision your first agent
helix identity provision \
  --forgejo-url http://localhost:3030 \
  --admin-user helio --admin-pass admin123 \
  --agent stepfun-tester \
  --ssh-key /path/to/agent-key.pub

# 5. Verify
helix identity list --forgejo-url http://localhost:3030

Provisioning an Agent

# Create the agent account in Forgejo
helix identity provision \
  --forgejo-url $FORGEJO_URL \
  --admin-user admin \
  --admin-pass $ADMIN_PASS \
  --agent my-coding-agent

# This creates:
#  - Forgejo user account (not a bot token)
#  - SSH key registration for git push
#  - PAT token for API access
#  - Scoped permissions (push to feat/*, open PRs, cannot merge)

Reviewing Agent Work

# Review dashboard — change management view for humans
helix review dashboard \
  --pr 1 \
  --repo owner/repo \
  --agent my-coding-agent \
  --tier provisional \
  --files changed_file.go,another.go

# What you see:
#  - Risk score with tier multiplier
#  - Blast radius: what depends on this change
#  - Architecture fit against ADRs
#  - Trust context: agent history, incidents, trends

# Strip bias from commit messages before review
helix review strip-bias --input commit-msg.txt

# Sign an evidence bundle (for audit trails)
helix review evidence sign \
  --input verdict.json \
  --key-role primary \
  --key-path /path/to/signing-key
