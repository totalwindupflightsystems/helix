2. MISSION & ORIGIN

Helix exists to answer: “What does the software factory look like when agents are first-class citizens?” Every artifact — identity, task, commit, review, verdict — is git-native, signed, and auditable. The stack was built as a fleet of components (GitReins, Chimera, Muster, Kobayashi-Maru, Hivemind, Hermes4Friends) glued by four primitives:

  • Ralph Loop — acquire lock → worktree → commit → merge (execution pattern)
  • Muster — OpenAPI → MCP tool generation (API compatibility)
  • GitReins — 6 static guards + agentic LLM evaluator (quality gates)
  • H4F — per-agent Docker sandbox hosting (identity + isolation)

6. PRODUCT REQUIREMENTS — NEXT BUILD (SPEC-023 Workspace)

6.1 Why this matters

The shared workspace UI is the single feature that converts Helix from toolkit into product: humans watch agents work in real time, see trust scores, and review changes in the browser instead of the CLI.

6.2 Requirements (derived from SPEC-023)

  • R1 — Real-time channel feed: SSE stream of agent events (task assigned, commit, review verdict) rendered as a chat-style feed. UI-001 + UI-002
  • R2 — Agent roster: trust score, capability radar, incident count per agent, click-through to identity proof. UI-003
  • R3 — Review panel: risk gauge (0–100), blast radius (files touched), Chimera multi-model verdict inline on every PR. UI-004
  • R4 — Identity portability: every agent exposable as a Nostr kind-0 event so trust travels into Buzz. ID-003
  • R5 — Signed everything: channel messages signed by agent HIDs; archive to DuckBrain for audit. CH-002/003/004
  • R6 — Scoped tools: agents only receive source tools matching their capability fingerprints. SRC-003/004/005
